Abstract

Deep research requires connecting multiple steps of search, reasoning, and computation, with intermediate findings guiding what to investigate next. As investigations grow, agents must maintain research state across model calls and check findings before errors propagate into subsequent work. We introduce PANINI-DR, a multi-agent harness that separates coordination of the overall investigation from the research and verification of individual subquestions. A shared workspace, built on the Generative Semantic Workspace representation, records subquestions, their dependencies, findings, and supporting evidence. Researchers investigate individual subquestions, while a separate verification agent checks proposed answers against those subquestions and their evidence. Verification feedback guides further investigation, and recorded findings inform subsequent assignments. We evaluate PANINI-DR on BrowseComp-Plus, FRAMES, and MoNaCo against seven state-of-the-art deep-research harnesses, all using a shared language-model backbone and frozen corpora. PANINI-DR achieves the strongest average performance across the three benchmarks. On BrowseComp-Plus, it achieves 73.3% accuracy, outperforming the next-best harness by 16.0 points. Its advantage is strongest on hard questions, where it answers nearly twice as many as the next-best harness. Ablations further show that structured planning and persistent state improve performance, as does checking each finding against its cited evidence before it is reused. Because a model can answer correctly from memory alone, we also analyze the evidence retained by each harness. PANINI-DR achieves the highest answer recoverability from saved evidence on all three benchmarks, while complementary claim-support audits show stronger evidence-backed answers. Accounting for this evidence changes how harnesses compare and further strengthens PANINI-DR's advantage.

How it works

PANINI-DR is built on two ideas. An Orchestrator coordinates the investigation; Researchers and a Verifier work on one subquestion at a time.

Explicit research state

A shared workspace, built on the Generative Semantic Workspace representation, records the subquestions, how they depend on each other, the findings, and the evidence behind them. The Orchestrator reads it to decide what is ready to investigate.

Verified findings before reuse

Researchers propose answers to single subquestions with cited evidence. A separate Verifier checks each proposal against its subquestion and evidence; rejections send the Researcher back to search. Only admitted findings feed the subquestions that depend on them, and calculations run in code.

Frequently asked questions
What is PANINI-DR?

PANINI-DR is a multi-agent deep-research harness for answering hard multi-step questions over a document collection. An Orchestrator coordinates the investigation through a shared research workspace, built on the Generative Semantic Workspace (GSW) representation, that records subquestions, their dependencies, findings and evidence. Researcher agents investigate individual subquestions, and a separate Verifier checks each proposed answer against its subquestion and cited evidence before it is reused.

Is PANINI-DR the same as Panini or GSW?

No. They are related work from the same lab. GSW (Generative Semantic Workspaces, AAAI 2026) is the structured representation that PANINI-DR's research workspace is built on. Panini (arXiv:2602.15156, ICML 2026) uses GSW for continual learning in token space; the code for GSW and Panini is at github.com/roychowdhuryresearch/gsw-memory. PANINI-DR (arXiv:2610.15208) is a separate deep-research harness for multi-step question answering; its code is at github.com/roychowdhuryresearch/panini-dr.

How well does PANINI-DR do on BrowseComp-Plus?

On BrowseComp-Plus (CF-150 split) PANINI-DR reaches 73.3% accuracy, 16.0 points above the next-best of seven state-of-the-art deep-research harnesses (SLEUTH, 57.3%), with all harnesses using the same language model (gpt-oss-120b), frozen corpora and retrieval service. On the hard questions it answers 52%, against 28% for the next best.

How does PANINI-DR compare on FRAMES and MoNaCo?

PANINI-DR has the best average accuracy across BrowseComp-Plus, FRAMES and MoNaCo (69.1, against 63.4 for SLEUTH). It also has the highest observed support, the share of answer credit that can be recovered from the evidence each harness saved, on all three benchmarks (average 60.9, against 49.6).

What makes PANINI-DR different from other deep-research agents?

Two ideas: research state is kept explicitly in a shared workspace instead of only in a growing conversation, and every intermediate finding is verified against its evidence before later steps use it. Ablations in the paper show that both the plan-and-state structure and verification improve accuracy.

How does PANINI-DR keep research state across agent calls?

Instead of relying on a long, growing conversation, PANINI-DR keeps the investigation in a shared workspace that pairs the plan (the subquestions and how they depend on each other) with the admitted findings, each with its evidence and a review status (verified, warned or derived). The Orchestrator reads this workspace to decide which subquestions are ready, and only admitted findings are passed to the subquestions that depend on them.

How do I check that my installation reproduces the paper's code?

Run panini-dr verify. It replays recorded model, reranker and embedding responses from FRAMES questions through your installation, on a CPU with no network, and requires its answers and traces to match those of the code behind the paper exactly. Reproducing the paper's numbers themselves needs the model servers and the benchmark data; REPRODUCE.md in the repository gives the commands, and live runs vary slightly because the LLM server is not bit-deterministic.

How do I run PANINI-DR on my own dataset?

Write your questions as questions.jsonl and your documents as docs.jsonl, run panini-dr prepare to build the corpus and its search indexes, then panini-dr run on the prepared folder and panini-dr score to grade the answers. The repository README has the exact formats and commands.

Is the PANINI-DR code available?

Yes. The code is open source under the Apache-2.0 licence at github.com/roychowdhuryresearch/panini-dr. It includes the paper configuration, the graders, benchmark preparation scripts, support for running on your own dataset, and panini-dr verify, a CPU-only check that an installation reproduces the paper code's decisions exactly.
